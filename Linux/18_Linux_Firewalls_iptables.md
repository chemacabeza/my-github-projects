# 18: Linux Netfilter & iptables Architecture

<p align="center">
  <img src="images/firewall_architecture.png" alt="Linux Firewall Architecture" width="800"/>
</p>

A firewall is not a separate application on Linux; it is a set of hooks built directly into the **Netfilter** framework of the Linux Kernel. `iptables` is the interface we use to talk to these hooks. 

To master `iptables`, you must stop thinking of it as a list of rules and start thinking of it as a **Packet Processing Factory**.

---

## 1. The Kernel Hook Points

Every packet entering or leaving your system hits specific "Checkpoints" in the kernel. These are the **Chains**:

1.  **PREROUTING:** Hits before any routing decision. Used for changing the packet's destination (`DNAT`).
2.  **INPUT:** Hits if the packet is destined for a local process.
3.  **FORWARD:** Hits if the packet is just passing through (routing from one interface to another).
4.  **OUTPUT:** Hits for packets generated by local processes.
5.  **POSTROUTING:** Hits just before the packet goes out on the wire. Used for changing the packet's source (`SNAT`/`MASQUERADE`).

---

## 2. The Five Tables: Specialized Workshops

Packets don't just hit chains; they are processed by **Tables** within those chains. Order matters.

| Table | Purpose | Common Targets |
| :--- | :--- | :--- |
| **Filter** | The default workshop. Decides if a packet should live or die. | `ACCEPT`, `DROP`, `REJECT` |
| **NAT** | Address translation workshop. Changes IPs and Ports. | `SNAT`, `DNAT`, `MASQUERADE` |
| **Mangle** | Specialized packet alteration (TTL, TOS). | `MARK`, `TOS`, `TTL` |
| **Raw** | Performance optimization. Bypasses connection tracking. | `NOTRACK` |
| **Security** | Used for Mandatory Access Control (MAC) via SELinux. | `SECMARK` |

---

## 3. The `conntrack` State Machine

`iptables` is at its most powerful when it is **Stateful**. The kernel tracks every connection and labels packets based on their history.

*   **NEW:** The first packet of a connection (e.g., a TCP SYN).
*   **ESTABLISHED:** Packets belonging to a connection seen in both directions.
*   **RELATED:** Packets starting a *new* connection but associated with an existing one (e.g., FTP data port).
*   **INVALID:** Packets that don't belong to any known stream. **Destroy these immediately.**

```bash
# Allow established traffic (CRITICAL for a working firewall)
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
```

## 4. Practical Rule Engineering

### A. The "Lockdown" Pattern
Drop everything by default and only open specific holes.

```bash
# 1. Set default policies
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# 2. Allow Loopback (Crucial for system health)
iptables -A INPUT -i lo -j ACCEPT

# 3. Allow incoming SSH (Port 22)
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
```

### B. Port Forwarding (DNAT)
Exposing an internal Docker container (172.18.0.5:8080) to the public internet (Port 80).

```bash
iptables -t nat -A PREROUTING -p tcp --dport 80 -j DNAT --to-destination 172.18.0.5:8080
```

### C. Rate Limiting (DOS Protection)
Drop connections if an IP tries to connect more than 5 times in 60 seconds.

```bash
iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m recent --set
iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m recent --update --seconds 60 --hitcount 5 -j DROP
```

---

## 5. Persistence: `iptables-save`

The kernel's `iptables` rules are stored in volatile RAM. If you reboot, **they are erased**.

```bash
# Save to file
iptables-save > /etc/iptables.rules

# Restore from file (usually added to network start script)
iptables-restore < /etc/iptables.rules
```

## 6. Lab: The Sandbox

Create a `docker-compose.yml` to test your rules without locking yourself out of your actual machine.

```yaml
services:
  firewall-node:
    image: alpine
    cap_add:
      - NET_ADMIN  # REQUIRED to touch iptables
    command: /bin/sh -c "apk add iptables && sleep infinity"
```

*This module provides the low-level foundation for UFW and Firewalld. You now understand the hooks that actually secure the Linux Internet.*
